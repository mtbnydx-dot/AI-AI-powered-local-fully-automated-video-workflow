# 视频生产 agent 工作指南

本指南约束离线生产中的操作范围。agent 可以读取包、验证配置、运行和恢复任务、查看记录并整理结果。提示词内容与资产制作属于外部模块；不要在生产过程中自行改写、删减、补写或重新组合创作要求。

## 运行前

1. 确认实际分支、配置、脚本包和输出目录，先执行 `videopipe validate`。不把本地 CPU 测试或 HTTP 模拟测试当作真实 B200 验证。
2. 确认镜头顺序、计划时长、尺寸和第一帧绑定。旧 `reference_images` 第一张参与生成，其余只参与审核；可选 `asset_bindings` 明确区分这两个用途。
3. 新包把完整有效文本放入 `prompt`，`negative_prompt` 留空。旧包正负字段会在输入兼容步骤形成运行快照，之后冻结；同时保留 `input-package.json` 供查看原输入。不要在审核或重试时再追加负面词或反馈。
4. 确认所需 H3、Qwen、ASR 权重已在本地，记录实际模型路径、版本与配置。ASR 缺失是可记录的功能不可用，不是要求 agent 自动联网下载或阻断生产。

基本命令与完整参数见 [使用说明](usage.md)。典型顺序如下；这些是操作示例，不代表本分支已经在 B200 运行成功：

```bash
videopipe validate /data/episode/package.json --config configs/b200.yaml
videopipe run /data/episode/package.json --config configs/b200.yaml --output /data/runs/episode-001
videopipe status /data/runs/episode-001
videopipe resume /data/runs/episode-001
```

## 生成和审核

- 每轮每镜头最多 3 次生成；不要把“重试 3 次”理解为首次之外再来 3 次。恢复或普通定点重试不会重置预算。额外一轮必须由操作者明确使用 `retry --new-round`，历史累计数不清零。
- 原提示词、对白与资产绑定不随审核变化。正常生成重试只改变记录中的 seed，不能通过 `parameters` 偷换这些输入。
- 审核只判断实际看见的明显画面问题。不要从稀疏截图推断台词、口型同步或精确动作时刻，不因合理风格变化和轻微差异反复重做。
- 未通过达到上限后随机保留一个已完成、可解码的 take。记录问题后继续队列；不依据分数暗中改成择优，也不新增每镜头人工审计。
- 审核不可用时，从已有可用 take 中随机选择一个并告警。无法解码的文件不能参加随机保留；没有可用视频的镜头报告缺失，其他独立镜头继续。
- ComfyUI 超时后先检查已记录的提交和服务端状态。不要假定超时等于没有开始，也不要宣称本实现提供跨进程 exactly-once 保证。

## ASR 和字幕

ASR 默认关闭。需要时在既有 Python 环境安装可选依赖，再配置本地模型：

```bash
python -m pip install -e '.[asr]'
```

```yaml
asr:
  enabled: true
  model: /models/faster-whisper-large-v3
  gpu: 7
  compute_type: int8_float16
  language: zh
  timeout: 600
```

每个合成版本运行一次独立 ASR 子进程，使用单输入推理、单 worker 和词级时间戳；它不会建立 HTTP 服务。模型只从本地目录或已有缓存读取。缺少依赖、模型、CUDA 库、超时或推理失败都会返回 `status=unavailable` 并保存原因；关闭时返回 `disabled`。当前 faster-whisper 官方说明列出的 GPU 依赖为 CUDA 12 的 cuBLAS 与 cuDNN 9，实际 B200 环境仍需验证其已安装版本组合。[faster-whisper 官方说明](https://github.com/SYSTRAN/faster-whisper)

字幕仅提取原始有效 `prompt` 的 `<d>[语言]台词</d>`。输出保留原台词及标点，语言标签和 H3 连续性控制标记不当成对白。匹配忽略大小写与标点，保留字母语言的词边界；中文按汉字比较。镜头时间窗由实际参与拼接的片段时长计算，不按可能有误差的计划时长计算。只有真实 ASR 词或整句时间范围落在该镜头内且文字对应时才输出；重复台词按原台词顺序使用最早的后续匹配。缺词、跨镜头或只有不能拆开的长句段落会留下未对齐记录。ASR 文本和时间字段在子进程结果入口统一校验，字幕不再增加一套校验或概率拒绝阈值。

SRT 使用 UTF-8 BOM，时间来自 ASR，不按字符数量猜测，不给缺失台词均分时长。完全没有可靠匹配时不产出 SRT；部分匹配时只输出可靠部分，并在 `subtitles.json` 中列出遗漏。字幕和 Qwen 文字差异判断互不依赖，任何 ASR 差异、缺失或未对齐都不会触发重生成、增加人工闸门或阻断既有人工终审。

## B200 分工与实测边界

默认 GPU 0–6 运行生成及片段超分；GPU 7 是完整 B200，由 Qwen 审核进程和按需启动的 ASR 子进程共享。这里不使用 MIG。`CUDA_VISIBLE_DEVICES` 只是设备选择，vLLM 的显存比例只是其自身预算；它们不是跨进程显存隔离，也不保证 ASR 峰值。不要添加不存在的 ASR 硬显存上限参数。

启动顺序、Qwen 权重和 vLLM 参数见 [部署说明](deployment.md)。首次实测应记录 Qwen 常驻、ASR 启动与实际推理的显存峰值、耗时和错误。若不能共存，先记录 ASR 不可用、调整明确的部署配置再复测，不要为满足文档而宣称已经共存成功。

## 完成条件与小型验收

本地测试覆盖预算及流水线行为；真实硬件验收另外运行短样本，并记录以下结果：

1. 一个 T2VA 和一个单第一帧 I2VA，实际请求中的有效提示词在所有 take 间保持相同。
2. 连续画面拒绝最多产生 3 次生成，然后随机保留可解码视频，进入片段超分及合成。
3. 服务不可用、失败或恢复不会清空累计数，也不会让一个问题镜头阻塞其他独立镜头。
4. ASR 台词差异只成为报告；SRT 时间来自真实识别，缺失对白不会出现伪造时间。
5. 检查片段顺序、时长、尺寸、音轨、降级记录和人工终审状态。

提交结果时区分“单元测试通过”“CPU/HTTP 联调通过”“真实 B200 样本完成”“人工终审通过”。不以目录存在、进程启动或模型加载成功代替后续状态。

## 修改代码时

- 为推测性竞态或极少发生的安全边界增加机制前，先说明具体故障、发生概率及依据、代码量和维护成本，并取得用户明确同意。没有统计就写概率未知，不能用理论健壮性扩大范围。
- 外部数据在输入包、模型响应等入口校验一次，内部传递确定类型的值，不逐层重复防御。
- 主函数表达正常流程；复杂细节放到有明确名称的辅助函数。不要为仅出现一次的简单语句提前抽象。
- 注释解释不明显的约束与反直觉行为，不复述代码。
- 内置 workflow 和样例由脚本生成；改生成脚本再生成，不手改生成结果。
- 使用仓库现有 unittest、HTTP 测试服务和 FFmpeg 流程，测试真实实现；不在测试里复制业务算法，尽量少用 mock。
- 不引入新的工具、鉴权、调度平台或额外审核节点。需要扩大范围时先列出具体收益和成本。
